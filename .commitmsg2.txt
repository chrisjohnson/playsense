fix download: read renamed items[].item; dedupe in-page duplicates

Verified against a real 5345-entry dev-mode account, two bugs surfaced:

1. The Feb-2026 API renamed the playlist entry's track object from
   items[].track to items[].item (the old key comes back null), so every
   entry was silently skipped and a full download ended 'done' with 0 rows.
   download.py now reads entry.get("track") or entry.get("item") and skips
   non-track types.

2. A playlist can contain the same track twice. A row added earlier in the
   same page is not visible to db.query() until flush, so the second
   occurrence created a second Track object and the page commit died with
   'UNIQUE constraint failed: tracks.spotify_track_id'. Keep a per-page
   map of pending track objects and reuse it for repeated ids.

Result: la crema (5345 entries) now downloads to 5324 unique tracks and
classifies (5324 classified, llm_used=false). AGENTS.md documents the
rename.
